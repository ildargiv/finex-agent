# Ликвидация фондов FinEx: рабочий стол пайщика

## Когда использовать
- «Что нового по FinEx», «есть новости по выплатам», «что пишут на форумах», «вышел новый документ?».
- «Сколько я получу», «сколько стоят мои паи», «стоит ли продавать брокеру с дисконтом», «выгоден ли выкуп».
- «Вот сообщение из группы / письмо брокера / ответ ликвидатора — сохрани и проверь».
- «Мой портфель такой-то», «добавь фонд», «вот отчёт депозитария».

## Главная идея
1. **Память — в хранилище, а не в голове.** Всё лежит в `~/finex-desk/` (переменная `FINEX_DESK`):
   портфель, архив документов с текстом, новости, форумы, входящие от пользователя, котировки, СЧА,
   допущения модели, отчёты, `journal.md`. Перед работой прочитай `references/case-facts.md`, хвост
   `journal.md`, последний `reports/payout-*.md` и `python scripts/status.py`.
2. **Первоисточник решает.** Факт о ликвидации считается установленным, только если он есть в документе
   ликвидаторов, суда, ЦБ Ирландии, НРД/Мосбиржи или в письменном ответе брокера. СМИ, форумы и Telegram —
   гипотезы со статусами ✅/⚠️/💬/❌ (`references/sources.md`).
3. **Цифры — с датой и источником.** СЧА, котировки, курс, удержания — никогда из памяти модели.
4. **Личные данные пользователя не покидают его компьютер.** Портфель, количества, отчёты брокера, номера
   счетов живут только в `FINEX_DESK`. Не вставляй их в поисковые запросы, не публикуй, не отправляй третьим
   лицам, не коммить в репозитории.

## Инструменты (`scripts/`, Python 3.9+, только stdlib; для PDF — `pypdf`)
| Скрипт | Что делает |
|---|---|
| `portfolio.py list/add/remove/import/fund/funds` | Портфель паёв; импорт ISIN и количеств из отчёта депозитария/брокера (.ods/.xlsx/.csv); справочник фондов |
| `docs.py [--add URL] [--get URL] [--read X --summary] [--list]` | Следит за страницами FinEx, ликвидатора, ЦБ Ирландии, Мосбиржи, НРД; новые PDF скачивает в `docs/` и извлекает текст; показывает изменения страниц |
| `news.py [--days N --all] [--tickers] [--add-query] [--add-feed]` | Google News RSS (RU/EN) по ликвидации FinEx -> `news.jsonl`, ⚑ по ключевым словам |
| `forums.py [--add URL] [--sources]` | Новые сообщения Smart-Lab и публичных Telegram-каналов (`https://t.me/s/<канал>`) -> `forums/<дата>.md` |
| `intake.py add/list/status` | Входящие от пользователя: пересланные сообщения закрытых групп, письма брокеров, предложения выкупа, файлы -> `inbox/` со статусом проверки |
| `prices.py [тикеры] / quote / history / moex` | Последняя биржевая цена MOEX (историческая) и котировки/предложения выкупа с источником |
| `payout.py [тикер] / nav / navs / params` | Ожидаемая выплата на пай: СЧА -> резерв ликвидатора, комиссия, расходы, замороженные активы -> дисконт за срок -> ₽ по курсу ЦБ; 3 сценария; сравнение с рынком; итог по портфелю |
| `status.py [--run]` | Сводка: непрочитанные документы, ⚑-новости, непроверенные входящие, последний расчёт. `--run` — весь сбор подряд |

Запуск: `python <папка_навыка>/scripts/<скрипт>.py ...`. Типовые места: Hermes (Windows) —
`%LOCALAPPDATA%\hermes\profiles\finex\skills\finance\finex-liquidation\`, Hermes (Linux/macOS) — `~/.hermes/...`,
OpenClaw — `~/.openclaw/skills/finex-liquidation/`, Claude Code — `~/.claude/skills/finex-liquidation/`.
В Windows, если `python` не найден, пробуй `py` или `python3`.

Справочники (в Hermes — `skill_view(finex-liquidation, <путь>)`):
- `references/case-facts.md` — **что установлено по делу**: юрлица, суд, ликвидаторы, хронология, механизм выплат, санкции. Читать первым; обновлять, когда факт подтверждён документом.
- `references/sources.md` — где искать: официальные сайты, регуляторы, суд, брокеры, СМИ, форумы, Telegram; правила проверки и статусы.
- `references/payout-model.md` — модель выплаты, откуда брать СЧА, смысл каждого допущения, как сравнивать с выкупом.

## Процедуры

### 0. Портфель
1. Если пользователь дал отчёт депозитария/брокера — `portfolio.py import <файл> --dry-run`, покажи найденное,
   после подтверждения — без `--dry-run`. Иначе `portfolio.py add TICKER QTY`.
2. Неизвестный ISIN или валюта класса — уточни по документам и `portfolio.py fund TICKER --isin ... --ccy ...`.
3. Для каждого фонда без СЧА — найди СЧА на пай (процедура D) и внеси `payout.py nav`.

### A. Плановый мониторинг («что нового по FinEx»)
1. `status.py --run` (или по отдельности `docs.py`, `news.py`, `forums.py`).
2. **Каждый новый документ** открой и прочитай целиком (текст лежит рядом с PDF). Выпиши: дата, кто издал,
   что решено, что меняется для держателей через НРД, сроки, суммы, что требуется от пайщика. Отметь
   `docs.py --read <файл> --summary "..."`. Если факт новый — обнови `references/case-facts.md` (с датой и ссылкой).
3. ⚑-новости открой; подтверди или опровергни по первоисточнику. Форумные сообщения о сроках, выплатах,
   выкупе, лицензиях — проверь и отметь статусом в своём ответе.
4. Предложения выкупа и котировки (в новостях, на форумах, от пользователя) — `prices.py quote ... --kind buyback --source ...`.
5. `payout.py` — пересчитай, если появились новые СЧА, котировки, курс сильно изменился или поменялись допущения.
6. Ответ: TL;DR (что изменилось и важно ли это для пользователя) → новые документы и факты → новости/форумы
   со статусами → таблица «рынок vs выплата» → что сделать пользователю (если нужно: подписать согласие у
   брокера, подать данные, не продавать/продавать — решение за ним).

### B. Пользователь принёс сведения (Telegram-группа, другой брокер, письмо, скриншот)
1. `intake.py add --source "<откуда>" --text "<дословно>" [--file ...] [--tags ...]` — сохрани дословно, без правок.
   Перед сохранением убери из текста чужие персональные данные (телефоны, ФИО частных лиц), если они не нужны для дела.
2. Оцени: кто источник, что утверждается, можно ли проверить. Ищи подтверждение в документах ликвидаторов,
   у брокеров, в СМИ. Поставь статус `intake.py status <id> ✅|⚠️|💬|❌ --note "чем подтверждено"`.
3. Если внутри есть цена выкупа/дисконт — `prices.py quote`; если СЧА/суммы выплат — `payout.py nav` (источник = это сообщение, статус в source).
4. Предложения «выкупа через знакомого брокера» из чатов проверяй особенно жёстко: лицензия ЦБ РФ (cbr.ru,
   справочник участников финрынка), юрлицо, способ расчёта. Признаки мошенничества называй прямо.

### C. «Сколько я получу» / «продавать ли с дисконтом»
1. Проверь, что СЧА по всем фондам портфеля свежие (дата не старше последнего фактшита/отчёта ликвидаторов).
2. `payout.py` (по портфелю) и `payout.py TICKER` (разложение по фонду). Курс ЦБ скрипт берёт сам.
3. Сравни предложение выкупа с базовым и пессимистичным сценарием: какую доходность в год даёт ожидание
   (`(выплата/цена)^(1/лет) − 1`) и что за риски (санкционное разрешение для НРД-цепочки не получено,
   спор о комиссии 3%, судьба замороженных активов, курс рубля, налоги).
4. Ответ: таблица, допущения явно, «точной суммы на пай ликвидаторы не публиковали». Это аналитика, решение за пользователем.

### D. Поиск СЧА (NAV) на пай
Порядок: уведомления и отчёты ликвидаторов → фактшиты на finexetf.com (раздел Fact sheets; по форумам, в
фактшитах на 23–24.07.2026 указана СЧА каждого фонда — проверить) → финансовая отчётность ICAV (NAV per share
по классам паёв) → последние СЧА до заморозки 2022 (только как ориентир, отметить). Внеси
`payout.py nav TICKER <СЧА на пай> --ccy <валюта класса> --date <дата оценки> --source "<документ, URL, стр.>"`.
Если опубликована только СЧА фонда целиком — раздели на число паёв в обращении из того же документа.

## Правила (обязательные)
- **Не выдумывай** сроки, суммы, решения суда, лицензии. Нет документа — так и говори: «не подтверждено».
- **Различай** держателей через НРД (выплаты только после санкционных разрешений) и держателей вне цепочки НРД.
  Пользователь, у которого паи учтены в НРД/российском депозитарии, — первая категория.
- **Пиши в хранилище.** Документ без пометки «прочитан», непроверенное входящее, котировка без источника — незаконченная работа.
- **Приватность.** Портфель и документы пользователя не выходят за `FINEX_DESK`; в веб-поиске — только общие запросы
  (тикеры, названия фондов), никогда количества, ФИО, номера счетов.
- Сделки не исполняешь, доступы к брокерскому счёту и Госуслугам не просишь, персональные данные третьим лицам не отправляешь.
  Формы, анкеты, согласия — готовишь черновик и объясняешь, подписывает и отправляет пользователь.
- Ответ на русском, сначала вывод. Суммы — в ₽ с разрядами, СЧА — в валюте класса паёв, доли — в %.
- Если сайт не отдаёт данные скрипту (JS, защита) — открой его браузером/веб-инструментом среды и сохрани
  документ через `docs.py --get`, отметь это.
